# hackaton-time — «Происшествие»

3D-кооператив в браузере: эвакуация из многоэтажки при землетрясении и первая помощь во дворе. Мультиплеер по LAN, локальные ИИ-агенты, всё работает без интернета.

- **ТЗ и кто что делает:** [`docs/tz/README.md`](docs/tz/README.md)
- **Правила для агентов:** [`AGENTS.md`](AGENTS.md)

```bash
npm install
npm run db        # Postgres в Docker: постоянные аккаунты и прогресс; ждёт готовности БД
npm run dev       # сервер :3000 + клиент :5173 → http://<ip>:5173 с любого ноута в сети
npm run start     # демо: сборка клиента + https://<ip>:3000 (самоподписанный сертификат)
npm run check
```

Песочница мини-игр и чанков: `/sandbox`. Переменные (необязательно): `PORT`, `HTTPS=0|1`, `DATABASE_URL`, `OLLAMA_URL`, `OLLAMA_MODEL`.

Обычный запуск требует PostgreSQL: если база недоступна, сервер останавливается
с понятной ошибкой, чтобы не создавать аккаунты, исчезающие после перезапуска.
`npm run db` хранит данные в Docker-томе `pgdata`; не удаляйте этот том при перезапуске.
При своей установке PostgreSQL задайте `DATABASE_URL` в `.env`.
Проверка `/api/health` должна показывать `"db":"postgres"`.
Имя и пароль существующего игрока вводятся на вкладке «Вход»; регистрация — «Новый игрок».
Для временного демо без сохранения нужно явно включить `ALLOW_MEMORY_STORE=1`.
Redis для аккаунтов и сессий не требуется: они уже хранятся в PostgreSQL.

Проверка сохранения на настоящей БД: задайте `TEST_DATABASE_URL` и запустите
`npm run test -w server -- --run test/persistence.test.ts`.
Тест создаёт отдельного временного игрока и удаляет только его данные.

Нужно: Node.js 20.9+. Для ИИ на сервере — [Ollama](https://ollama.com) с локальной моделью (скачать заранее).
