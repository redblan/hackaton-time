## N13 — объекты для агентов

`src/requested.ts` добавляет объекты по существующим `when`/`unless`.
Все флаги по умолчанию выключены. Включение флагов — AI/сервер, не генератор.
Мелкие предметы декоративные, не перекрывают путь игрока.

| Флаг | Чанки | Мировые координаты и результат |
|---|---|---|
| `spawn_first_aid` | `e1f6`–`e1f9` | Шкафчик у стола `[4.8, y, 9.7]`, аптечка на полке `[4.8, y + .8, 9.7]`; y — пол этажа |
| `spawn_ladder` | `y00`, `y10` | Лестницы `[11.4, 0, -1.1]`, `[23.4, 0, -1.1]`, в стороне от козырьков и входов |

| `power_on` | `y20` | Тёмная головка фонаря сменяется светлой в `[27, 4.3, -6]` |
| `spawn_exit` | `e1f1` | В южной стене открывается второй проём x=9.1..10.9, высота 2.4 м; основной выход сохранён |

Интеграция Юры для N13: свет по `requested-lamp-on.pos` (в контракте мира нет
`kind: light`); для нового выхода — убрать накладную покраску, внутреннее окно,
подоконник и радиатор у x=10 на первом этаже первого подъезда при `spawn_exit`.
Геометрия/коллизии проёма уже заданы в данных. Декор `Interior` сейчас рисуется
отдельно от чанка и не учитывает этот флаг. Пока он не обновлён, визуально
второй выход нельзя считать готовым.

## N14 — палитра админки

`src/palette.ts`: `PALETTE` — 11 пресетов: аптечка, фонарь, вода, коробка,
огнетушитель, стул, кружка, одеяла, лестница, шкафчик, ограждение.
У каждого есть `id`, русская `label`, общий `size`, основной `color`, `parts`.
Каждая часть задаёт `pos`, `size`, `color`. Координаты локальные: Y=0 — низ,
X/Z — относительно места установки. Никаких дополнительных ассетов/зависимостей.

`paletteObjects(presetId, instanceId, pos, rotY, collide)` превращает пресет
в совместимые `WorldObject` (`box`), поворачивает смещения частей и назначает
уникальные ID с префиксом экземпляра. Админка должна сохранять этот префикс,
чтобы удалять все части одного экземпляра через `world:patch.remove`.

Экспорт `world/chunks/palette.json` требует фильтрации файлов в загрузчике
сервера и корневом walk: сейчас они считают каждый JSON чанком.
Собственный `world/scripts/walk-check.ts` уже фильтрует имена чанков.
Пока остальные фильтры не готовы,
нельзя класть туда каталог палитры: он станет 31-м «чанком» без `objects`.

## Зависимости

N11 ждёт контракта `kind: prop` в `shared/src/world.ts` от Егора.
Контракт `kind: crowd` и рендер G12 появились в main (0442360); N12 подключён
через `addCrowd` в generateWorld и включён в JSON-чанки.
Генератор не обходит отсутствующий контракт prop через приведения типов
или JSON с неподдерживаемым kind.

Пользователь подтвердил: контракты и загрузчики готовит Егор.

Независимая подготовка выполнена: `src/propPlacements.ts` содержит 8 предметов
на этаж (144 всего), массы и отскок. `replaces` указывает старую статическую
коробку, которую нужно убрать при подключении prop. Переносимые предметы
лежат на полу, а не на декоративном комоде без коллизии.
`src/crowdPlacements.ts` содержит 15 жителей двора, 8 животных (4 кошки и
4 собаки), 18 голубей (6 на козырьках) и по 2 соседа в каждом подъезде.
Максимум 8 NPC в чанке. Seed вычисляется из стабильного ID. Маршруты замкнуты
внутри одного чанка; тест проверяет каждый отрезок с учётом габарита тела,
отсутствие пересечений со статическими препятствиями и наличие опоры.
План предметов N11 пока не включён в generateWorld и JSON: физика предметов
появится после контракта prop Егора и G11 Юры. Толпа N12 уже рисуется модулем
G12 Юры; `validateWorld` проверяет seed, маршруты и лимит количества NPC.
