# ТЗ команды: «Толчок» — эвакуация и первая помощь при землетрясении

Сценарий игры (что происходит по шагам): документ «Сценарий: Землетрясение — эвакуация и первая помощь» (ссылка у Егора).
Здесь — **кто что делает, в каких папках и в каких форматах**.

## Архитектура в одной картинке

```
                ноут-сервер (Егор, 48 ГБ)                          ноуты-клиенты
┌──────────────────────────────────────────────────────┐     ┌──────────────────┐
│ server/   Node + Socket.IO + Postgres     (Егор)     │◄───►│ браузер:         │
│   ├─ вызывает ai/        мозг NPC         (Матвей)   │ LAN │ client/ (Vite +  │
│   ├─ вызывает shared/scenario  логика игры (Юра)     │     │ React Three Fiber)│
│   └─ раздаёт world/chunks/*.json  мир     (Никита)   │     │                  │
│ Ollama (локальная LLM)                               │     └──────────────────┘
└──────────────────────────────────────────────────────┘
```

- Сервер — **единственный источник правды**: состояние прохождения, позиции, БД, ИИ.
- Клиент — только браузер: рисует мир, шлёт действия игрока, показывает мини-игры.
- Интернета на демо нет. Всё (модель, ассеты, шрифты) лежит локально.

## Папки и владельцы

| Папка | Что там | Владелец |
|---|---|---|
| `shared/src/*.ts` (кроме scenario) | **Контракты**: id, форматы мира, ИИ, сети | Егор |
| `shared/src/scenario/` | Генератор прохождения, редьюсер сценария, журнал, оценка | **Юра** |
| `client/src/minigames/` | Мини-игры (React-оверлеи) | **Юра** |
| `ai/` | NPC: база знаний, карточки персонажей, движок реплик, память, диспетчер 112 | **Матвей** |
| `world/` | Генератор чанков, ассеты (glb), `world/chunks/*.json` | **Никита** |
| `client/src/world/` | Отрисовка чанка (компонент ChunkView) | **Никита** |
| `server/`, `client/src/core/` | Сеть, вход, чанки, БД, камера, управление, HUD, склейка | Егор |

**Правило №1:** работаешь только в своих папках. Нужно изменить контракт в `shared/src/` или чужой код — пишешь Егору.

## Контракты (читать до начала работы)

- `shared/src/ids.ts` — общий словарь: роли, NPC, навыки, этапы, предметы, интерактивные объекты, зоны, события NPC.
- `shared/src/world.ts` — формат чанка мира.
- `shared/src/scenario/types.ts` — генератор, состояние, события, эффекты сценария.
- `shared/src/ai.ts` — запрос/ответ NPC, память игрока.
- `shared/src/minigame.ts` — пропсы мини-игр.
- `shared/src/net.ts` — сообщения сети (для понимания, как всё связано).

Как модули стыкуются, на примере «игрок залез под стол»:

1. Никита поставил в чанк `{ kind: "interactable", target: "cover_table", ... }`.
2. Игрок жмёт E → клиент шлёт `game:event { type: "interact", target: "cover_table" }`.
3. Сервер прогоняет событие через `reduce()` Юры → эффекты: `journal(ok)`, `npcSay(papa, quake_started)`, `stage(pack)`.
4. На `npcSay` сервер зовёт `ai.say()` Матвея → реплика папы стримом уходит игроку.

## Запуск

```bash
npm install          # из корня репы, один раз
npm run check        # типы + тесты всех модулей — перед каждым коммитом
npm run world        # пересобрать world/chunks/*.json
npm run chat -- papa # консольный чат с NPC (модуль Матвея)
```

Клиент и сервер появятся в репе в ближайший час (Егор). До этого Матвей, Юра и Никита работают в своих модулях автономно — у каждого есть свой способ проверить работу без игры.

## Как работаем в git

1. `git checkout main && git pull`
2. `git checkout -b <имя>/<что>` — например `matvey/knowledge-base`
3. Маленькие коммиты. Перед коммитом `npm run check` — зелёный.
4. `git push -u origin HEAD` → Pull Request → CI зелёный → Squash and merge.
5. После мержа: `git checkout main && git pull`.

Мержим часто, раз в 1–2 часа. Большой PR вечером = конфликты и сломанная демка.
