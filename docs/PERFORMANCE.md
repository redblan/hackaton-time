# Оптимизация статического мира и Piper (Никита)

Изменения `client/src/world/` и `ai/` выполняются Никитой по прямому поручению
пользователя. Новых зависимостей нет. Форматы мира и сетевые контракты сохранены.

## Неподвижные коробки

`ChunkView` использует обычный Three.js InstancedMesh. Матрицы и цвета записываются
в layout effect, когда изменяется массив видимых коробок (чанк или флаги).
Покадровой подписки для них нет. Границы меша пересчитываются после обновления,
включая замену объектов при неизменном количестве, поэтому отсечение камерой
не скрывает ступени. Столкновения по-прежнему считает getColliders.

## Кеш декора этажей

`floorResourceCache` хранит до 6 комплектов и примерно 32 МиБ буферов геометрии
и mipmaps текстуры табличек. В комплект входят геометрия отделки, мебель и двери,
материалы и атлас подписей. Ключ — подъезд и этаж. Трансформации подвижных створок
не кешируются: у каждого отображаемого экземпляра своя анимация и состояние двери.

Кеш LRU, активные комплекты закрепляются счётчиком ссылок. При вытеснении
освобождаются геометрия, текстура и собственные материалы. Общий solidMaterial
при этом не удаляется. Лимиты могут временно превышаться, если все ресурсы
используются открытыми сценами; после освобождения лишние записи удаляются.
В нормальной игре активны не более трёх чанков; данные и коллизии по-прежнему
ограничены 3/30. Кеш — только декоративные ресурсы, не дополнительные чанки.

Получение ресурсов выполняется при commit, не во время render: отменённый
рендер и двойной запуск эффектов StrictMode не оставляют лишних ссылок.
Проверка `floorResourceCache.stats()` показывает объём, число записей, повторных
использований и построений. Для явной очистки неиспользуемых записей — clearIdle().
Объём приблизительный: учитываются массивы и RGBA mipmaps, не накладные расходы
драйвера, скомпилированные программы и JavaScript-объекты.

## Piper

Настройки createTts (необязательные поля TtsOptions):

| Поле | По умолчанию | Назначение |
|---|---|---|
| maxQueue | 4 | Максимум ожидающих задач, плюс одна выполняющаяся |
| maxQueueWaitMs | 5000 | Срок ожидания в очереди; истёкшая фраза возвращает null |
| maxCacheBytes | 16777216 | Бюджет LRU WAV, 0 выключает кеш |
| timeoutMs | 10000 | Ограничение выполнения одного процесса Piper |

При переполнении новая фраза пропускается без исключения (null), текст игры
остаётся доступным. Совпадающие голос, темп и нормализованный текст используют
одну задачу синтеза. Кеш также ограничен 200 записями; слишком большой WAV
возвращается вызывающему коду, но не сохраняется. Текст длиннее 2000 символов
после нормализации пропускается, чтобы ограничить размер заданий.
При таймауте процесс завершается; следующая задача ждёт его закрытия.
stats() возвращает running, waiting, cacheBytes, cacheEntries, synthesized, dropped.

## Проверки и пределы выводов

Тесты проверяют обновление матриц, цветов и границ, отсутствие покадровых записей,
LRU и освобождение закреплённых/свободных ресурсов, повторное использование
реального комплекта этажа и лимиты при посещении всех 18 этажей. Для Piper —
переполнение, срок ожидания, дедупликация, бюджет WAV, отключение кеша и ошибки.
Тесты графики выполняются без GPU, атлас подписей — с подменой canvas.
Piper в нагрузочных тестах подменён; реальные голоса требуют установленного Piper.

Проверки: npm run check, npm run build, тест спуска с тремя чанками и задержкой
сети, полный обход карты. Прибавка FPS и время GPU требуют замеров в браузере;
тесты подтверждают сокращение повторных построений и загрузок буферов,
но не доказывают конкретный прирост FPS.
