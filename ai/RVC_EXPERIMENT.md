# RVC: состояние эксперимента

Рабочая игра продолжает использовать Piper. `RVC_ENABLED` по умолчанию выключен.
Все Python-зависимости, исходники и модели: `C:/Web/rvc-experiment`, вне репозитория игры.
CPU-окружение: `venv/Scripts/python.exe`. Python 3.12.10, PyTorch 2.7.1+cpu.

## Стенд
- `measure.py`, `report.json`: синтез Piper + преобразование и короткий замер Ollama.
- `tune.py`, `tuning.json`: число потоков.
- `latency_tune.py`, `padding-tuning.json`: аудиоконтекст; лучший измеренный тёплый результат 2285 мс, без Piper.
- `example-0.wav`: первый образец; `padding-0.2.wav`: вариант с сокращённым контекстом.
- `worker.py`: прогретый CPU-процесс на 127.0.0.1:17865, **только стендовая привязка papa → ShrekRus**.
- `client.py`: внешняя команда `--npc papa --input INPUT.wav --output OUTPUT.wav`.
- `download_gpu.py`, `gpu-download.log`: докачка CUDA wheel частями, итоговая SHA256 проверяется по официальному индексу. Не считать CUDA установленной до успешного импорта/замера.

## Адаптер игры (ещё не включён)
В `ai/src/rvc.ts` нет Python-зависимостей: только запуск внешней команды.
Настройки считываются при создании TTS:
- `RVC_ENABLED=1` — явное включение; отсутствие/0 — Piper.
- `RVC_BIN` — абсолютный путь к внешнему executable, например отдельному python.exe.
- `RVC_ARGS` — JSON-массив аргументов, например путь client.py. Shell не используется.
- `RVC_TIMEOUT_MS` — максимум ожидания внешней команды, по умолчанию 3000 мс.
Команда получает `--npc`, `--input`, `--output`. Успешный выход и корректный WAV обязательны; ошибка, отсутствие сервиса, битый WAV или таймаут возвращают исходный Piper.
Модели/очередь прогреваемого процесса должны быть готовы до включения. Cache разделён по NPC в режиме RVC.
